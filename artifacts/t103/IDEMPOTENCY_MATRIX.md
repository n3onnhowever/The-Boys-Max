TestTransport receipts are keyed by attempt_id only, NOT by outbox_id. Therefore the tests would observe duplicate business submissions across distinct delivery attempts; the mock does not hide duplicates using an outbox uniqueness constraint.

Guarantee: PostgreSQL business state and final delivery state, rather than BullMQ job identity or Redis contents, fence replay. Queue jobs can execute again. SUCCEEDED means API acceptance in live code, not proven actual receipt by a user. UNKNOWN can conservatively suppress an unsent message (fence commits before governor). Availability/automatic delivery under all crashes is not promised.
